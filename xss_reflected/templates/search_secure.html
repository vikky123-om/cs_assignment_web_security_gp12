📖 Other Mitigations (Theory)

  • Context-aware Output Encoding (applied above): Encode all user input before injecting it into the DOM. The encoding must match the context: HTML body (&lt;), HTML attributes, JavaScript context, or URI component.
  • Framework Auto-Escaping: Utilize modern web templating engines (Jinja2, React, Angular) that auto-escape interpolated expressions by default. Never bypass auto-escaping with insecure directives such as | safe or dangerouslySetInnerHTML.
  • HTML Sanitiser for Rich Text: If rich HTML input is permitted (e.g., Markdown or WYSIWYG editors), process input with a strict allow-list sanitiser like Bleach or DOMPurify to strip dangerous elements (<script>, <iframe>, onerror=).
  • Content Security Policy (CSP): Deploy a restrictive HTTP response header like Content-Security-Policy: default-src 'self'; script-src 'self'. This prevents the execution of inline scripts and unauthorized external scripts even if an injection flaw exists.
  • HttpOnly Session Cookies: Protect session identifiers by setting the HttpOnly flag. Even if malicious JavaScript is executed via XSS, the browser blocks access to document.cookie, preventing session hijacking.
  • Safe DOM Sinks: When updating client-side UI via JavaScript, prefer safe APIs like element.textContent or element.setAttribute() instead of vulnerable sinks like element.innerHTML or document.write().

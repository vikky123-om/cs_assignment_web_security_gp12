VULNERABLE Account Deletion via GET

Root cause: The deletion endpoint is a simple GET request (/delete-account) without any CSRF token. An external website can issue this request using an embedded image tag <img src="..."> without user interaction.

Delete Account (Vulnerable GET)

SECURE Account Deletion via POST + CSRF Token

Mitigation implemented:
1. Strict HTTP POST method: GET requests cannot alter server state.
2. Synchronizer CSRF Token: Form includes a hidden cryptographic token _csrf_token matched against the active session. Cross-site requests cannot guess or read this token.

📖 Other Mitigations (Theory)

  • Avoid state-changing GET requests (implemented above): According to RFC 7231, GET must be safe and idempotent. All state-changing actions (deletions, password resets, transfers) must require POST, PUT, or DELETE.
  • Synchronizer Token Pattern (implemented above): Issue a cryptographically random, per-session anti-CSRF token in each state-changing form and validate it strictly on the server before mutating state.
  • SameSite cookie attribute: Setting SameSite=Strict or SameSite=Lax on the session cookie instructs browsers not to attach session cookies to cross-site requests, neutralizing CSRF.
  • Re-authentication for critical actions: Require the user to re-enter their current password or complete an MFA step before proceeding with high-impact operations like account deletion.
